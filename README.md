# dsh-urllib（网址库）

一个**独立运行**的本地网址收藏夹：双击桌面「网址库」就能看、能加、能复制，**不需要 DSH 开着**。

## 怎么用

- **打开**：双击桌面上的「网址库」图标。
  - 它会先看一眼 `127.0.0.1:3090`：没在跑就以**隐藏窗口**启动本地服务，然后打开浏览器。
  - 你把所有网址库标签关掉后，服务在 **180 秒**内没有请求就**自己退出**，不留常驻进程。
- **加网址**：页面右上角「＋ 添加网址」——链接、名称、标签（多个，逗号分隔）、备注。
- **复制**：每张卡上的绿色「复制」。
- **用浏览器打开**：每张卡上的「🌐 用浏览器打开」，走系统默认浏览器。
- **在独立窗口打开**：页面顶部那个按钮，把网址库本身从工作台 iframe 里拎出来单独开一个窗口。
- **按颜色筛选**：标签筛选条下面有一条「**颜色**」筛选条，点一个颜色就只看那种颜色的卡片，再点一次取消。
  只在真的用到颜色时才出现（一张彩色卡都没有时整条隐藏）；「默认」也是可筛的一项。
  搜索、标签筛选、颜色筛选是**同时满足**的关系，当前生效的条件会写在标题下面那行统计里。
- **主题**：**默认白底（浅色）**。工具栏右侧有「☀ 浅色 / 🌙 深色 / ⧉ 跟随工作台」三档，选择记在浏览器本地。
  「跟随工作台」只在被工作台同源 iframe 嵌入时有意义：读宿主背景色算亮度，亮则浅色、暗则深色，
  所以配色是成套切换的，不会出现深底配浅色按钮的错配。
- **卡片颜色**：在「添加网址 / 编辑」对话框里的「**卡片颜色**」那一行选，五个选项：**默认 / 红 / 黄 / 蓝 / 紫**。
  背景保持纯白；选了颜色后，卡片用同色水洗 + 同色细描边 + 柔和投影 + 内侧高光做淡淡的玻璃感。
  颜色存在 `library.json` 的 `color` 字段里，跟着数据走；选「默认」会删掉该字段。
  卡片左上角那个小圆点只是**颜色标识**，不可点。页面**不会自动**给卡片分配颜色。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面本体。样式内联，**不依赖任何外部样式表**，离线可用 |
| `app.js` | 页面逻辑（原生 JS，无构建）。自动识别宿主 |
| `server.mjs` | 零依赖本地服务：发页面 + 读写数据 + 180 秒无人理自灭 |
| `start-urllib.ps1` | 启动器：探端口 → 按需隐藏启动服务 → 开浏览器 |
| `start-urllib.vbs` | 无闪窗外壳（桌面快捷方式指的就是它） |
| `install.ps1` | 安装/修复：找 Node、建空数据文件、重建本机桌面快捷方式 |
| `install.vbs` | 安装脚本的无闪窗外壳（**拷到新电脑后双击这个**） |
| `library.json` | **数据主存储**。页面、本地服务、DSH/agent 共写同一份 |
| `library.json.bak` | 每次保存前自动留的上一版 |
| `server.log` | 服务日志（启动、自灭、端口占用），排错用，可随时删 |

桌面快捷方式：`<桌面>\网址库.lnk` → `wscript.exe "<本目录>\start-urllib.vbs"`。
**启动器文件必须保持纯 ASCII**（Windows PowerShell 5.1 会把无 BOM 文件按 GBK 读，中文会被读坏）。

## 拷到别的电脑 / 分享给别人

整个文件夹就是完整项目：**约 60 KB、零第三方依赖、不需要构建**（`server.mjs` 只用 Node 自带模块，
没有任何 npm 包，所以不牵扯别人的代码和许可）。

**步骤：**

1. 把整个 `urllib` 文件夹复制到新电脑（U 盘、压缩包、网盘都行）
2. 双击文件夹里的 **`install.vbs`**
   - 找 Node.js；没找到会告诉你两种解决办法
   - 建一个空的 `library.json`（**已有数据则原样保留，不会覆盖**）
   - 在**当前这台机器**上重建桌面快捷方式
3. 双击桌面上的「网址库」图标就能用了

**唯一的硬性要求是有 Node.js**（14 或更新）。不想装也行——把 `node.exe` 直接放进这个文件夹，
脚本会优先用它，等于绿色免安装版：

```
urllib\
  node.exe        <-- 从 nodejs.org 下的 zip 里解出来放这里
  server.mjs
  ...
```

**分享给别人时注意个人数据：**

- `library.json` / `library.json.bak` 是你的网址收藏
  - 只分享工具 → 删掉这两个文件，对方的 `install.vbs` 会自动建一个空的
  - 想把收藏一起送 → 留着，对方打开就是你的清单
- `server.log` 是排错日志，可以删

**挪了位置就要重跑一次 `install.vbs`**：桌面快捷方式里存的是绝对路径，文件夹换电脑、换盘、
改名字之后，快捷方式会指空。重跑一次即可，数据不受影响。

**换端口**：默认 3090。若新电脑上 3090 被占用，设一个用户环境变量 `URLLIB_PORT=3091` 即可
（启动脚本和服务都会读它）。

**macOS / Linux**：`start-urllib.ps1` / `.vbs` / `install.*` 都是 Windows 专用。那边直接在
文件夹里跑 `node server.mjs`，然后浏览器打开 `http://127.0.0.1:3090/` 就行，页面和数据完全一样。

## 两种宿主，同一个页面

`app.js` 启动时看自己的地址决定后端：

| 地址 | 模式 | 数据接口 |
| --- | --- | --- |
| `/api/worktable/site/<目录>/index.html` | `dsh` | dsh-worktable 的 `/api/worktable/file`、`/api/worktable/write` |
| `/` （由 `server.mjs` 提供） | `local` | 本地服务的 `/api/file`、`/api/write` |

- `dsh` 模式：多出「加入工作台项目卡」按钮（它要写 DSH 那个源的 localStorage，跨源做不到）。
- 拖进工作台的浏览器窗格时，若同源则主题跟随宿主；跨源时自动退回自身深色配色。

## 本地服务的接口与安全边界

零依赖，只认这几个路由：

- `GET /`、`GET /app.js` — 页面
- `GET /api/config` — 返回数据文件路径与接口前缀
- `GET /api/ping` — 心跳（页面每 20 秒一次，用于保活）
- `GET /api/file?path=…` / `POST /api/write {path, content}` — 读写

**安全边界**：`path` 只允许 `library.json` 和 `library.json.bak` 这两个绝对路径，其他一律 `403` —— 客户端不能借它读写任意文件。只绑定 `127.0.0.1:3090`，不对外网开放。

排错日志：本目录下的 `server.log`（只记启动、自灭、端口占用，可随时删）。

## 数据格式（`library.json`）

```json
{
  "schema": "dsh-urllib/v1",
  "updatedAt": "2026-09-12T14:03:21.123Z",
  "items": [
    {
      "id": "u_m1b2c3x9z",
      "url": "https://example.com/docs",
      "title": "示例文档",
      "note": "里面那节讲重试策略，以后要抄",
      "tags": ["参考", "文档"],
      "color": "blue",
      "opens": 3,
      "addedAt": "2026-09-12T13:00:00.000Z",
      "lastOpenedAt": "2026-09-12T14:00:00.000Z"
    }
  ]
}
```

- `id` — 唯一，`u_` + base36 时间戳 + 随机后缀。**改已有条目不要改 id**，页面按 id 匹配。
- `url` — 必填，`http/https`。
- `title` — 可空；空则页面显示域名。
- `note` — 可空，一句话说明「留着它干什么」。
- `tags` — 字符串数组、自由词，建议 1~12 个。
- `color` — 可选，卡片主题色，只能是 `"red"` / `"yellow"` / `"blue"` / `"purple"` 之一。
  **不写（或写别的值）就是「默认」无色卡片**，页面不会自作主张给它配色。
- `opens` — 数字，点「用浏览器打开」时自增，用于排序。
- `addedAt` / `lastOpenedAt` — ISO 字符串；没打开过就是 `""`。
- 顶层 `schema` 固定 `dsh-urllib/v1`，`updatedAt` 每次改动更新。

## 给 DSH / agent 的约定（重要）

用户可以直接说「把这次聊到的资料收进网址库」，此时：

1. **先读** 本目录的 `library.json`，看已有条目的标签用词，新条目尽量复用，不要造同义词。
2. **追加/最小修改**：只在 `items` 末尾追加，或改指定 id 的字段；不要重排、不要重写整个文件、不要动别人的条目。
3. 更新顶层 `updatedAt` 为当前时间。
4. 保持 JSON 合法、UTF-8、2 空格缩进，写完整文件（写文件即整文件覆盖）。
5. 写完就够了 —— 页面每 5 秒轮询，会自动载入并提示「检测到外部更新」。**不管网址库是独立开着还是挂在工作台里，这一步都一样。**
6. 页面每次操作都是「读磁盘最新 → 改 → 写」，所以不会覆盖 agent 刚写进去的条目。
